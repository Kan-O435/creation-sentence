# 週次note記事：一括作成プロンプト

以下をそのままAIに渡し、`【入力】` だけを書き換える。

```markdown
このリポジトリの `skills/note-weekly-pipeline/SKILL.md` に従い、週次note記事を1案件分作成してください。

## 【入力】

- テーマ候補: <例：マッチングアプリで会話が続かない>
- 記事の目的: <例：無料記事で検索流入と信頼を作る / 有料記事の購入を検証する>
- 想定読者: <例：マッチ後に数往復で会話が終わり、改善点が分からない人>
- 著者が実際に持つ経験・一次情報: <箇条書き。なければ「なし」>
- 書いてよい個人的な数値・結果: <箇条書き。なければ「なし」>
- 書いてはいけないこと・避けたい表現: <箇条書き。なければ「なし」>
- 価格方針: <無料 / 有料。未定なら「未定」>
- 既存記事としてつなげたいもの: <パスまたは「なし」>
- 目標公開日: <YYYY-MM-DD。未定なら「今週」>
- 補足: <任意>

## 実行してほしいこと

1. テーマを鵜呑みにせず、検索意図・競合の方向・noteとの相性を調査する。時点で変わり得る情報はWebで確認し、URL・確認日・不確実性を `01-research/research.md` に記録する。検索量、順位、売上、購入数は確認できない限り推測しない。
2. SEOのPrimary Queryを1つ選び、タイトル・記事の約束・読者課題を決める。競合の焼き直しではなく、独自の切り口を明記する。検索上位や収益を約束しない。
3. `python3 skills/note-weekly-pipeline/scripts/new_issue.py` で新規案件を作る。既存の案件・`research/` は上書きしない。
4. `00-brief/` から `03-source/` までを埋める。著者の体験は `author_fact`、解釈は `author_interpretation`、外部情報は `external_fact`、仮説は `hypothesis`、架空例は `fictional_example`、不明は `unknown` として区別する。
5. `04-draft/article.md` に完成原稿を書く。無料記事は2,500〜4,500字、有料記事は4,500〜8,000字を目安にするが、文字数で水増ししない。少なくとも以下を含める。
   - 読者の具体的な状況から始まる導入
   - 独自のフレームワークまたは判断基準
   - 3〜5個の行動可能な節
   - チェックリスト、テンプレート、比較、または明示した `架空例` のいずれか
   - 限界・当てはまらないケース
   - 自然な次の行動
6. 著者が提供していない経験、収益、成功談、期間、数字、引用、スクリーンショットを創作しない。架空例は必ず `架空例` と見出しで明示する。因果関係・効果・成果を断定しない。
7. `04-draft/claim-ledger.md` に、本文の非自明な主張と根拠を全件記録する。外部事実にはURLと確認日を記録する。
8. `05-package/seo-topic-map.md` に、今回の記事から派生する次の記事候補を3〜5件作る。各候補に Primary Query、検索意図、読者課題、独自の約束、記事形式、内部導線、検証状態、次の検証方法を記録する。
9. `publish.yml` に、platform、無料/有料、価格、タグ、サムネイル状態、カテゴリ状態を記録する。原稿を `prepare_package.py` で `05-package/article.md` へコピーする。Platform固有の仕様が不明なら `needs-publication-settings` とする。
10. 最後に `validate_issue.py` を実行し、エラーを解消する。完了報告では、作成した案件パス、公開原稿パス、SEO Primary Query、価格方針、公開前の未解決事項だけを簡潔に示す。

## 成功条件

- 1案件が `output/YYYY-MM-DD-<slug>/` に自己完結している。
- 記事は検索意図に答え、読み終えた読者が次の一歩を選べる。
- 事実・仮説・架空例が混ざっていない。
- 月5万円は目標として扱い、未検証の収益予測として本文に書かない。
```
